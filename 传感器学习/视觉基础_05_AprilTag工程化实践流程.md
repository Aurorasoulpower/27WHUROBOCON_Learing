# AprilTag 工程化实践流程

> 用途：写今年 AprilTag 视觉模块时，用作最小实现流程和检查规范。
> 本文不展开算法推导，原理见
> [AprilTag 定位原理](视觉基础_02_AprilTag定位原理.md)，
> 完整公式见
> [AprilTag 定位数学推导](视觉基础_03_AprilTag定位数学推导.md)。

## 1. 总体链条

```text
配置
  -> 启动检查
  -> 采集最新帧
  -> 检测目标标签
  -> PnP 求位姿
  -> 质量判断
  -> 坐标变换
  -> 时序处理
  -> 标准结果输出
```

实现时每一段只做一件事。不要把所有步骤塞进一个函数，也不要在检测函数中直接控制底盘。

## 2. 先定义接口和配置

开始写算法前，先确定：

- 目标标签 ID；
- 标签家族，例如 `DICT_APRILTAG_36h11`；
- 标签实际边长，单位米；
- 相机设备；
- 分辨率、帧率和像素格式；
- 标定文件；
- 输出坐标系；
- 最终结果由谁使用。

配置项应集中管理，并带明确单位，例如：

```text
device
width / height / fps / fourcc
calibration_path
dictionary
target_id
marker_length_m
max_reprojection_error_px
max_distance_m / min_distance_m
pose_timeout_ms
```

同一参数只保留一个来源，不要在多处分别硬编码。

## 3. 启动阶段

启动阶段完成一次性工作：

1. 检查必需配置；
2. 读取相机标定 `K`、`D`、`image_size`；
3. 创建标签字典和检测参数；
4. 打开相机并设置采集模式；
5. 读取第一帧；
6. 检查实际分辨率、帧率和格式；
7. 确认实际分辨率与标定分辨率一致。

任一项失败都应给出明确错误。不要用“近似内参”或错误分辨率继续运行却不提示。

启动日志至少包括：

```text
实际设备
实际图像尺寸 / 格式 / 帧率
标定文件及标定尺寸
标签字典 / 目标 ID / 标签边长
输出话题或通信接口
```

## 4. 图像采集

推荐使用独立采集线程：

```text
读取图像
 -> 记录采集时间
 -> 增加帧序号
 -> 覆盖共享的最新帧
 -> 通知处理线程
```

处理线程只取最新帧，不处理大量积压旧帧。

每帧需要有：

```text
frame
sequence
capture_time
```

采集失败时进入重试或安全状态，不能无限阻塞整个程序。

## 5. 标签检测

处理步骤：

1. 根据通道数转换为灰度图；
2. 使用固定字典检测标签；
3. 得到 `ids` 和 `corners`；
4. 按目标 ID 选择标签；
5. 检查 `ids` 与 `corners` 数量一致；
6. 检查所选角点是否完整。

不要默认使用第一个检测结果。画面中可能同时存在其他标签。

无目标时返回：

```text
valid = false
reason = no_target
```

不要伪造 `x=0, y=0, yaw=0`。

## 6. 位姿计算

使用以下输入执行 PnP：

```text
目标标签四角点
相机内参 K
畸变参数 D
标签实际边长
```

输出：

```text
rvec
tvec
```

并转换为：

```text
R_camera_tag
t_camera_tag
```

计算前检查：

- 标签边长是否为正；
- 内参与图像尺寸是否匹配；
- PnP 输出数组长度是否正确；
- 平移是否在合理范围；
- 角点是否位于图像范围内。

## 7. 质量判断

先做简单、有效的检查：

```text
是否检测到目标 ID
距离是否合理
重投影误差是否超限
相邻帧位姿是否明显跳变
数据是否过期
```

运行时的重投影误差用于判断本帧几何一致性，不代表绝对精度。

建议返回明确的失败原因：

```text
no_frame
no_target
pose_failed
range_invalid
reprojection_invalid
jump_invalid
stale
```

## 8. 坐标变换

先明确坐标链：

```text
camera -> tag -> TR -> handoff
camera -> BR base
```

计算类似：

```text
T_base_handoff =
    T_base_camera *
    T_camera_tag *
    T_tag_tr *
    T_tr_handoff
```

原则：

- 每个变换写明方向；
- 每个平移写明单位；
- 轴线换向不等于相机安装外参；
- 固定安装偏移使用完整齐次变换或集中配置；
- 不要散落多个 `x + 常数`。

## 9. 时序与滤波

无效帧不进入数值滤波。

需要维护：

```text
last_valid_time
last_pose
filter_state
```

静止测量可以对有效样本做均值或中值；yaw 使用循环平均。

连续控制可使用轻量低通或指数滑动平均，但应同时观察原始值和滤波值。

超过过期阈值后，不再把旧位姿当作当前结果交给控制端。

## 10. 结果输出

推荐结果结构：

```text
valid
reason
stamp
tag_id
frame_id
translation
rotation
reprojection_error
processing_ms
lag_ms
```

接口要求：

- 单位和坐标系明确；
- 无效结果有明确语义；
- 时间戳跟图像走；
- 不把 yaw 塞进标准消息的 `position.z`；
- 优先使用米、弧度和四元数；
- 通信协议只在输出适配层处理。

## 11. 推荐实现顺序

1. 配置与标定读取；
2. 相机打开和实际模式检查；
3. 目标 ID 检测与角点输出；
4. PnP 和重投影；
5. 终端结果与本地预览；
6. 相机重连和帧超时；
7. 坐标外参；
8. 多帧统计或轻量滤波；
9. ROS 或串口接口；
10. 实时性和长时间运行测试。

不要一开始就同时调相机、坐标、ROS 和机构控制。

## 12. 最小验收清单

- [ ] 使用稳定设备名启动；
- [ ] 实际采集参数与配置一致；
- [ ] 标定分辨率与实际图像一致；
- [ ] 只接受正确 ID；
- [ ] 无检测时返回明确无效状态；
- [ ] 每帧结果带时间戳和坐标系；
- [ ] 能输出重投影误差；
- [ ] 相机关闭或断开时不会卡死；
- [ ] 已完成静态重复性测试；
- [ ] 已确认相机、标签和交接机构外参；
- [ ] 控制端能识别并处理无效或过期位姿。

这份清单通过后，再讨论复杂滤波、跟踪、检测器替换和比赛现场优化。
