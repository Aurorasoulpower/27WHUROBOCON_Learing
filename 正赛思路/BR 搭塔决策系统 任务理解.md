# 2027 Robocon BR 搭塔决策系统：任务理解与技术路线规划

**文档目的：** 核实任务边界与预期交付，梳理决策问题，比较可选技术路线，制定前期两周学习计划。

## 一、我的任务理解：BR 搭塔决策系统要解决什么？

### 1. 任务定位

我的任务是传感器组第 4 项：**决策系统——BR 搭塔**。

就校内赛的实操经验来说，对自动车如何完全实现自主还基本没有概念。BR 是全自动机器人，比赛开始后无法由队员临场干预。因此，决策系统不能只执行预先固定的搭塔顺序，而应根据实时赛场信息、任务执行反馈和对手行为，自主决定下一步行动，并在局势变化时调整策略。

### 2. 系统基本流程

| 环节 | 主要内容 |
|---|---|
| 信息输入 | 接收视觉识别、物块定位、机器人定位及其他相关模块提供的数据 |
| 状态维护 | 整合物块分布、各塔搭建进度、机器人状态、剩余时间等信息 |
| 策略决策 | 选择搭建目标、获取物块、安排任务顺序，权衡抢塔与继续搭建 |
| 任务执行 | 调用导航、取物、放置等功能模块 |
| 反馈调整 | 根据执行结果与赛场变化更新状态，必要时切换目标或重新规划 |

### 3. 我理解的我需要解决的核心决策问题

| 问题 | 需要考虑的因素 |
|---|---|
| **搭哪座塔？** | 各塔当前进度、可获取物块、预期得分、完成难度与耗时 |
| **是否抢塔、抢哪座塔？** | 对手搭建进度、公共建塔区的竞争、抢塔收益与机会成本 |
| **如何安排搭建顺序？** | 一座塔搭完再转向下一座，还是先搭多座塔的塔基、中段，再集中完成塔顶 |
| **如何分配有限资源？** | 每次最多携带两个物块时，如何安排取物、运输与放置，减少无效往返 |
| **如何应对局势变化？** | 物块被取走、目标被对手抢占、任务失败、定位变化或剩余时间不足时如何调整 |
| **如何兼顾整场比赛？** | 在自主搭塔的同时，考虑公共区域竞争、保护法则及后续得分机会，争取最终胜利 |

**初步认识：** 这不是简单的固定流程控制，而是一个受比赛规则约束、资源与时间有限、需要持续响应环境变化，并受到对手行为影响的动态决策问题。队内可以预先制定总体策略，但 BR 需要具备自主选择具体行动和调整计划的能力。

## 二、职责边界与待核实事项

目前仍需明确我的决策模块在整车系统中的位置，以及需要负责到什么程度。

### 1. 决策系统的职责范围

我的初步理解是，核心工作是搭塔策略，但策略需要通过整车系统落地。

| 涉及环节 | 当前理解 | 需要核实的内容 |
|---|---|---|
| 搭塔策略 | 选择目标塔、物块及任务顺序 | 是否由我独立负责完整策略 |
| 整车任务调度 | 协调搭塔任务与其他功能 | 是否属于我的职责，还是由独立的上层系统负责 |
| 模块调用 | 调用导航、取物、放置等功能 | 我需要输出高层任务，还是还需组织多个子任务 |
| 接口与联调 | 决策模块需要与其他模块通信 | 是否由我负责接口设计、协议约定及联调 |
| 异常处理 | 任务失败后更新状态并重新决策 | 各执行模块提供哪些反馈，谁负责具体的重试与恢复逻辑 |

**待确认：** 我的交付边界是搭塔策略模块，还是包含任务调度、模块协调与异常处理的 BR 高层决策系统？

### 2. 输入与输出接口

| 方向 | 需要明确的内容 |
|---|---|
| 视觉输入 | 物块类别、颜色、朝向、位置及识别置信度等 |
| 雷达与定位输入 | 机器人位置、目标位置及对应坐标系 |
| 执行反馈 | 任务成功或失败、实际结果、耗时及失败原因 |
| 决策输出 | 目标塔位、目标物块、下一项任务及必要参数 |
| 模块接口 | 数据格式、更新频率、调用方式、反馈机制与异常处理约定 |

目前各功能机构仍在独立制作和调试，完整接口可能尚未确定。后续需要与视觉、雷达及机构调试人员沟通，或遵循团队统一的接口规范。

## 三、可选技术路线

目前考虑三条主要路线。它们都需要处理比赛规则、执行反馈与动态状态；区别在于，**决策主要由显式建模与搜索计算产生，还是由交互学习得到，或者两者结合。**

### 路线 A：规划与优化主导

**核心思路：** 将搭塔决策建模为带有约束、耗时、收益和状态变化的优化问题，通过规则约束、收益评估和搜索算法选择行动。
**类似这样**：
$$U(a)=P(a)G(a)−λT(a)−μR(a)$$
$$P(a) 是成功概率，
G(a) 是得分，
T(a) 是耗时，
R(a) 是风险。$$

| 主要模块 | 作用 |
|---|---|
| 状态建模 | 描述物块、塔进度、机器人状态、剩余时间及对手状态 |
| 规则约束 | 排除违反搭塔顺序、携带限制等规则的行动 |
| 收益评估 | 估计不同目标和任务顺序对最终比赛结果的影响 |
| 决策算法 | 采用贪心、搜索、滚动规划等方法选择任务 |
| 状态更新与重规划 | 根据实际执行结果和赛场变化重新计算 |

**优点**
- 决策依据较明确，便于分析、调试和解释。
- 能显式处理任务依赖、资源限制和硬性规则。
- 不必依靠大量试错训练才能形成初始策略。

**局限**
- 需要设计合理的收益模型，并估计任务耗时、成功率等参数。
- 复杂局势下，搜索空间可能快速增长。
- 对手行为与环境变化难以完全准确预测，规划结果需要持续更新。

### 路线 B：强化学习主导

**核心思路：** 建立能够模拟比赛交互的环境，让策略反复经历任务选择、环境变化和结果反馈，通过奖励学习如何安排搭塔任务，争取更高的整场比赛收益。

| 主要模块 | 作用 |
|---|---|
| 状态表示 | 将赛场局势、塔进度、资源、时间及对手情况转化为模型输入 |
| 行动设计 | 定义可选择的高层任务及目标 |
| 仿真环境 | 模拟任务执行、时间消耗、成功失败、资源变化及对手行为 |
| 奖励设计 | 以整场比赛结果为核心，引导策略学习 |
| 训练与评估 | 通过多轮仿真训练，并在不同局势下检验策略 |

**优点**
- 有机会学到复杂任务之间的长期关系，而非依赖人工逐条编写策略。
- 可以通过大量仿真尝试不同的搭塔顺序与竞争策略。
- 适合研究难以直接写出解析解的动态决策问题。

**局限**
- 需要构建足够可信的仿真环境，且环境与真实比赛之间存在差距。
- 状态、行动、奖励及训练方法的设计具有一定难度。
- 训练效果不保证最优，也不保证策略合法、稳定或能适应真实比赛。

### 路线 C：混合式决策

**核心思路：** 将规则约束、规划优化和强化学习结合起来，根据各自擅长的部分划分职责。

| 主要模块   | 可能的分工                      |
| ------ | -------------------------- |
| 规则约束   | 排除非法行动，保证硬性规则得到执行          |
| 强化学习策略 | 学习目标选择、任务优先级或长期收益评估        |
| 规划与优化  | 将策略目标落实为可执行的任务安排，必要时搜索更优顺序 |
| 执行反馈   | 更新状态，在任务失败或局势变化后重新决策       |

**优点**
- 可以兼顾规则约束、任务可执行性和学习复杂策略的能力。
- 能根据问题难度，把学习与搜索分配到不同决策环节。
- 允许先建立规划框架，再逐步引入学习模块。

**局限**
- 模块分工、信息传递和目标一致性需要仔细设计。
- 系统集成、调试和性能评估相对复杂。
- 如果职责划分不合理，可能增加复杂度，却没有明显改善效果。

### 三条路线的总体比较

| 维度 | 规划与优化 | 强化学习 | 混合式决策 |
|---|---|---|---|
| 核心依据 | 显式模型与收益计算 | 仿真交互与奖励学习 | 模型计算与学习结合 |
| 对环境模型的要求 | 需要任务、耗时和状态转移等模型 | 需要可反复交互的训练环境 | 两者都需要，具体程度取决于分工 |
| 处理复杂长期策略 | 依赖搜索范围与模型质量 | 有机会从经验中学习 | 可结合学习与规划 |
| 可解释性 | 通常较好 | 取决于策略与模型 | 取决于模块设计 |
| 主要工程风险 | 模型误差、搜索复杂度 | 仿真成本、训练不稳定、泛化不足 | 系统复杂度、模块协同成本 |

**初步思考：** 目前不预设最终路线。规划与优化路线更依赖显式建模；强化学习路线更依赖仿真训练；混合路线则需要明确学习算法与规划器各自解决什么问题。后续应结合实际任务复杂度、仿真条件和学习成本进一步比较。

## 四、两周学习计划

**总体目标：** 理解 BR 搭塔决策的建模方法，掌握三条路线的基本原理与实现模块，形成可以进一步验证的系统设计思路。暂不以完成代码为主要目标。

### 第一阶段：共同基础（第 1—4 天）

| 时间    | 学习内容                              | 阶段产出         |
| ----- | --------------------------------- | ------------ |
| 第 1 天 | 梳理比赛规则、得分条件、抢塔与公共区域竞争、物块携带限制及保护法则 | 搭塔决策约束清单     |
| 第 2 天 | 学习决策系统的状态、行动、状态转移、收益与反馈概念         | 初步问题模型       |
| 第 3 天 | 梳理感知输入、任务执行、状态更新与异常处理的系统流程        | 决策系统流程图与接口需求 |
| 第 4 天 | 分析典型局势：多塔并行、抢塔、物块不足、任务失败和剩余时间不足   | 典型决策场景及待解决问题 |

### 第二阶段：分路线学习（第 5—10 天）

| 路线 | 学习内容 | 阶段产出 |
|---|---|---|
| 规划与优化 | 收益函数、硬约束、贪心算法、搜索与滚动规划；了解任务排序问题 | 规划优化模块图及适用场景分析 |
| 强化学习 | MDP、状态与行动设计、奖励、策略、价值函数、训练与评估；了解常见算法的基本区别 | 强化学习问题定义草案及仿真需求 |
| 混合式决策 | 学习规则约束、规划器与学习策略的组合方式，分析不同模块的职责边界 | 混合架构草案及模块分工 |


### 第三阶段：综合比较与方案设计（第 11—14 天）

| 时间        | 工作内容                                 | 阶段产出          |
| --------- | ------------------------------------ | ------------- |
| 第 11天     | 将三条路线应用于相同的搭塔场景，比较它们如何处理任务排序、抢塔和突发变化 | 同一场景下的路线对比    |
| 第 12-14 天 | 整理学习成果，明确当前推荐方向、仍需验证的假设和下一阶段计划       | 决策系统设计草案与后续计划 |

|---|---|
| **职责边界** | 当前理解是搭塔高层决策，但整车任务调度、模块调用、接口设计与联调是否也由我负责，仍需明确。 |
| **决策输入与输出** | 需要与视觉、雷达及机构调试人员确认可提供的数据、任务接口、执行反馈及异常处理约定。 |

| **技术路线选择** | 希望先完成基础学习与方案比较，再结合比赛问题、仿真条件和工程成本决定以规划优化、强化学习还是混合式决策为主。 |
| **近期预期成果** | 希望确认两周以学习、建模和方案论证为主，形成设计草案与下一阶段计划是否符合团队预期。 |

**总结：** 当前最重要的是把 BR 搭塔决策问题定义清楚，明确系统边界，并理解不同技术路线解决问题的方式。先通过两周学习形成有依据的技术判断，再推进方案实现与验证，避免过早绑定某一种算法。
