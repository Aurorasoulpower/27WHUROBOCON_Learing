# 任务①：塔基/中段精准放置——任务分析与技术路线

> 规则基线：[南邮史官规则v1.1](./南邮史官规则v1.1.md)。
>
> 本文讨论 BR 在 L1/L2 建塔处放置塔基或中段的视觉测量问题。导航、底盘运动、机械臂轨迹和释放机构不属于视觉模块本身，但视觉结果需要能够支撑这些模块完成对位、最终复测和释放决策。

## 一、任务分析

### 1. 任务本质

精准放置不是“看见绿色方块”这么简单，而是一条从目标识别到最终释放的测量链：

```text
确定当前要使用的建塔处
    -> 获得建塔处的空间位置和姿态
    -> 获得所夹持塔基/中段的空间位置和姿态
    -> 计算两者的相对位置、方向和水平度误差
    -> 预测用品垂直投影是否能够完整落入建塔处
    -> 在结果稳定且可信时完成对位、复测和释放
```

其中任何一环缺失，都会出现“识别正确但放不准”的情况。视觉模块最终需要交付的是
可信的相对测量结果，而不是一个孤立的图像中心；但控制层、机构层和执行层的误差
同样会影响最终成功率。

### 2. 当前规则基线

与本题直接相关的 V1.1 规则事实如下：

| 项目      | 当前规则基线                          | 对任务的影响                       |
| --------- | ------------------------------------- | ---------------------------------- |
| 建塔处    | L1、L2 中的绿色 500 mm × 500 mm 方格 | 需要区分多个同类目标               |
| 塔基/中段 | 350 mm × 350 mm × 350 mm 立方体     | 有高度，不能只按二维正方形分析     |
| 尺寸公差  | 场地和道具尺寸可能存在约 ±5% 公差    | 标称尺寸不能作为绝对真值           |
| 塔顶      | 200 mm × 200 mm 立方体               | 后续叠塔会进一步改变边界风险       |
| 完整塔    | 两块塔基/中段竖直堆叠，再加一个塔顶   | 每层放置都可能影响后续建塔         |
| 建造顺序  | 塔基/中段 -> 塔基/中段 -> 塔顶        | 放错顺序会失去得分                 |
| 结束状态  | 被机器人触碰、夹持或承托的道具不计分  | 必须真正释放并脱离                 |
| 失败条件  | 塔基/中段触及规定区域以外的地面会失效 | 放置失误可能损失道具               |
| 调整条件  | 可重新调整己方已放置的塔基/中段       | 但需满足上方规则，且重新抓取有风险 |
| 塔保护    | 导致塔倒塌或偏离建塔处会强制重试      | 接近已建塔时的碰撞风险很高         |

V1.1 正文明确了“正确放置在建造点内”和建造顺序，但精确的空间判定仍需结合规则附录图纸、道具详图和裁判执裁。工程上适合采用更严格的判据：要求用品在地面的垂直投影完全位于建塔处内，并保留额外安全余量。

### 3. 规则目标与工程目标

需要明确区分三个层次：

| 层次     | 目标                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 规则目标 | 用品正确放置在建塔处内，顺序正确，最终与机器人脱离                       |
| 工程目标 | 中心尽量重合、相邻边尽量对齐、箱体保持水平，并保留足够边界余量           |
| 系统目标 | 对不同光照、视角、遮挡、振动和夹持状态稳定给出可信结果，不可靠时拒绝释放 |

“与边对齐”是降低风险的工程选择，不是规则对姿态的唯一要求。正方形具有 90° 旋转对称性，只需要控制到姿态角周期为 90° 的等价状态。

### 4. 规则对策略的约束

有几点会直接影响技术路线：

- 塔基/中段是正方体，视觉不能只看一条二维边。
- 一次严重的放置错误可能直接使该用品失效，不只是“少拿一点精度”。
- 已放置用品不能沿地面推、拖或滑动，释放后要纠正只能重新抓取。
- 机器人导致已建塔倒塌或偏离建塔处会强制重试，接近已有塔时需要更保守的避碰和释放策略。
- 比赛只持续三分钟，视觉算法不能为了追求测量精度而无限增加停留时间。
- L1 和 L2 高度不同，目标平面先验、相机可见范围和机器人姿态都会变化。

## 二、主要卡点与难点

### 1. 多个同类建塔处如何唯一确定并不是我们需要解决的

场地中存在多个绿色建塔处，颜色和形状高度相似，但是我认为这不应该由本模块解决。BR想要做到自主决策就需要决策系统综合雷达，相机给出的视觉信息和场上现在情况选择下一个搭塔的建塔处，并且决策出下一个要去哪个建塔处，我们要做的任务其实是，在导航到达建塔处附近时，用视觉手段辅助BR精准地对位放下物块。打个比方也就是说，导航和决策才决定选择哪个一个建塔处并且到达这附近，解决1-99的问题，我们只负责精确放下物块，解决99-100的问题。

### 2. 平面方形如何在斜视条件下稳定测姿

相机随 BR 运动，正方形在图像中通常呈梯形。图像外接矩形、近似多边形顶点或轮廓重心都不能直接作为精确的空间中心和姿态。

主要的误差来源包括：

- 车载视角下透视形变明显；
- 目标边缘受阴影、反光和涂装不一致影响；
- 四角靠近画面边缘时镜头畸变影响放大；
- 正方形存在 90° 姿态对称，角点排序不稳会造成角度跳变；
- 由四个点求平面位姿时可能存在镜像解或病态解。

因此，检测应尽量提取四条边界并检查其几何一致性，而不只是保存一组轮廓顶点。
姿态结果还需要借助“目标位于已知水平面”等物理先验消除歧义。

### 3. 相机测量如何落到机器人坐标系

相机给出的是目标相对相机的位姿，控制器需要的是目标相对机器人或夹持机构的关系。
中间至少涉及：

- 相机内参和畸变；
- 相机安装位置和朝向；
- 机器人运动学；
- 夹爪与塔基/中段之间的夹持关系；
- 图像与机器人状态的时间对应。

这些环节无法相互替代。相机标定准确，不代表安装外参正确；安装外参正确，也不代表每次夹取都没有偏差。最终放置失败必须能分辨是视觉、标定、夹持、运动还是释放造成的。

### 4. 相机是否需要/能够同时看到目标和用品

同时看清建塔处和塔基/中段当然可以做相对测量，但把它作为必要条件会降低鲁棒性：

- 塔基/中段很可能被夹爪或机器人本体遮挡；
- 地面目标和悬空箱体处于不同高度、不同平面；
- 旧图像、机器人位姿变化和运动模糊会同时影响两类观测。

所以在持块情况下，如何安装相机是一个需要仔细考量的问题，并且很难在此状态下看清楚建塔处，物块位置等等全部信息，要把遮挡等因素纳入考量。一要从代码算法角度优化，二要考量相机安装位置，尽可能获得更多信息。

更稳妥的主路线是：视觉测量建塔处，机器人运动学和夹持标定提供用品位姿。若相机同时看到用品，可将其作为夹持偏差的校验来源，而不是唯一数据源。

### 5. 夹持偏差和机构重复性

不能直接假设“用品中心等于夹爪中心”。需要考虑：

- 每次抓取中心偏移是否一致；
- 每次抓取角度是否一致；
- 用品在夹持过程中是否发生微小转动；
- 加速、减速和振动是否让用品相对夹爪移动；
- 释放瞬间是否产生回弹或滑移。

夹持偏差既可能通过机构设计和重复性测试控制，也可能通过视觉或额外传感器观测。
选择哪条路线，需要在精度收益、结构复杂度和比赛节奏之间权衡。

### 6. 尺寸公差和深度尺度（本条影响相对最小，正式场地会比较精确)

规则允许场地和道具约 ±5% 的尺寸偏差。若把 500 mm 和 350 mm 当成绝对精确值：

- 由外观尺寸推算距离会产生比例误差；
- 近远变化时深度尺度可能整体偏大或偏小；
- 边界余量的估计会过于乐观；
- 同一算法换一套实物后可能需要重新调参。

应保存实际测量尺寸和来源，并将尺寸误差纳入置信判断。平面高度、相机安装外参和机器人运动学也有可能提供额外尺度约束，需要在后续实验中比较不同组合。

### 7. 三维高度、倾斜和执行延迟

塔基/中段是 350 mm 高的立方体。仅有中心 \(x,y\) 和偏航角不足以完整描述风险：

- 箱体倾斜时，竖直边会增加水平投影范围；
- 夹持点与释放点之间可能存在视觉不可见的偏差；
- 视觉测量完成到真正释放之间存在运动延迟；
- 机器人振动会使最后一刻的位置变化。（本条比较突出)

如果机构能够保证箱体始终水平（这取决于最终的夹块机构如何持块) ，可以把俯仰和滚转作为机构约束处理；但仍应验证这一假设，并评估释放过程中的倾覆风险。

### 8. 识别成功不等于放置成功

视觉可能给出一个数学上合理、但系统上不可执行的结果。例如：

- 目标虽然识别正确，但相机外参已经变化；
- 相对位姿虽然准确，但夹持偏差没有计入；
- 当前位置够准，但释放瞬间会滑移；
- 预测边界虽然入框，但安全余量小于系统误差。

因此，最终判定必须落在整机闭环上，而不是只看检测帧或位姿重投影误差。

## 三、几何难度与精度预算

### 1. 名义尺寸下的边界余量

保持水平的 350 mm 塔基/中段相对 500 mm 建塔处发生偏航时，其轴对齐投影宽度为：

$$
w(\theta)=350(|\cos\theta|+|\sin\theta|)\text{ mm}.
$$

理想居中时单侧余量为：

$$
m(\theta)=\frac{500-w(\theta)}{2}.
$$

| 偏航角 | 最大投影宽度 | 理想居中时每侧余量 |
| -----: | -----------: | -----------------: |
|    0° |     350.0 mm |            75.0 mm |
|   15° |     428.7 mm |            35.7 mm |
|   30° |     478.1 mm |            11.0 mm |
|   45° |     495.0 mm |             2.5 mm |

这张表说明：

- 中心完全重合时，45° 在名义尺寸下仍然放得进去；
- 但 45° 几乎耗尽全部边界余量，其他误差必须接近零；
- “中心误差不超过 75 mm”只在边完全对齐时成立，不能作为通用精度指标；
- 中心和角度误差是耦合的，必须一起检查。

如果建塔处取公差下限 475 mm、塔基/中段取上限约 367.5 mm，45° 时的理论单侧余量约为 **−22.4 mm**。因此不能依赖“正方形刚好能转进去”的理想几何关系。

### 2. 用保守的投影判据代替单个阈值

工程上可把塔基/中段的底面四角或完整三维轮廓投影到建塔处平面，再计算每条边界的最小有符号距离。只有所有投影点都位于边界内，并且最小余量大于系统不确定度与释放漂移时，才认为位置足够安全。

这个判据比单独设置“横向误差、纵向误差、角度误差”更合理，因为它直接对应边界风险。
具体安全余量不能在缺少实验数据时拍板，应由视觉误差、夹持误差、运动误差和释放漂移共同确定。

## 四、坐标链与技术模型

### 1. 坐标系

建议用以下抽象对象讨论，不绑定具体代码结构：

| 符号  | 含义                   |
| ----- | ---------------------- |
| \(B\) | BR 机器人基准坐标系    |
| \(C\) | 相机坐标系             |
| \(E\) | 夹爪或末端执行器坐标系 |
| \(K\) | 当前塔基/中段坐标系    |
| \(G\) | 当前选定的建塔处坐标系 |

使用 \(T_{A B}\) 表示“把 B 坐标系中的量变换到 A 坐标系”。所有计算必须明确方向、
单位、时间和适用条件。

### 2. 关键变换链

```text
T_B_G = T_B_C * T_C_G
T_B_K = T_B_E * T_E_K
T_G_K = inverse(T_B_G) * T_B_K
```

其中：

- \(T_{C G}\) 由建塔处视觉测量得到；
- \(T_{B C}\) 来自相机安装关系；
- \(T_{B E}\) 来自采集时刻的机器人运动学；
- (T_{E K}) 来自夹持关系或额外观测；
- \(T_{G K}\) 是控制器最终关心的相对位姿。

这个模型的价值在于把“识别绿色区域”和“控制用品放置”连成一条可解释链路。

### 3. 时间同步是精度问题

相机随 BR 运动时，旧图像配新位姿会直接产生平移和角度误差。因此图像、相机位姿和机器人运动学必须按采集时刻对应。若夹爪在运动，静止时采集和低速复测应优先于高速连续测量。

最终释放前最好有两类检查：

1. 当前视觉结果与短时间历史结果是否一致；
2. 结果从采集到执行是否仍在允许时效内。

### 4. 坐标实现的讨论

坐标变换可以先由程序内部的矩阵计算完成，再决定是否接入 ROS TF2。TF2 适合管理已知的静态安装关系和动态机器人关系，但不负责发现相机外参错误、判断视觉目标是否有效，也不能替代夹持标定。

因此，技术路线的重点是先验证每个变换的来源和误差，而不是先追求一棵形式完整的坐标树。

## 五、技术路线讨论

### 1. 总体路线

建议采用“传统几何视觉为主、机器人运动学补齐用品位姿、可靠性判断控制释放”的路线：

```text
建塔处检测
    -> 多候选筛选
    -> 相机坐标中的建塔处位姿
    -> 结合机器人运动学和夹持关系
    -> 塔基/中段相对建塔处位姿
    -> 边界余量和时序稳定性判断
    -> 对位、复测和释放决策
```

这条路线不要求塔基/中段始终可见，也不会把目标检测结果直接误当成控制量。

### 2. 建塔处检测

第一选择仍是颜色与几何结合的传统视觉，原因包括：

- 建塔处颜色有明确的场地参考；
- 目标形状固定，几何约束强；
- 过程可解释，便于现场调参；
- 不需要先建立大规模训练集；
- 计算量更容易满足比赛节奏。

检测应同时关注颜色一致性和边界质量。候选项需要经过形状、面积、可见性和位置先验筛选。任务层负责决定使用哪个建塔处，视觉层负责报告候选和歧义状态。

如果真实场地测试证明颜色分割在复杂光照下无法稳定工作，可以考虑使用分割模型或与传统边缘检测结合。检测框式 YOLO 的主要输出不是精确边界，无法单独解决本题测量问题，因此不作为首选。

### 3. 建塔处位姿测量

在相机标定可靠的前提下，可结合四个边界角和已知平面几何估计建塔处在相机中的位姿。
需要重点验证：

- 目标靠近和远离时，深度变化方向与尺度是否正确；
- 横向移动和旋转时，姿态符号是否正确；
- 斜视情况下姿态是否稳定；
- 多个平面高度下是否仍能保持精度；
- 局部边界不可见时是否能够识别风险。

如果四角测量受遮挡影响明显，可进一步探索基于边缘直线、局部可见边和已知矩形的约束估计。技术选择应由实测误差决定，而不是一开始锁定某一种求解器。

### 4. 用品位姿获取

可用路线有三类：

| 路线                                 | 优点                     | 主要风险                           | 当前定位       |
| ------------------------------------ | ------------------------ | ---------------------------------- | -------------- |
| 建塔处视觉 + 机器人运动学 + 夹持标定 | 不要求用品可见，链路清晰 | 夹持偏差和运动学误差会直接进入结果 | 推荐主路线     |
| 同时观测建塔处和用品                 | 可直接估计夹持偏差       | 遮挡、不同高度平面和双目标误差耦合 | 校验路线       |
| 仅用品视觉定位                       | 不依赖运动学             | 用品常被夹爪遮挡，姿态估计困难     | 暂不作为主路线 |

两条路线可以组合：主路线保证连续工作，同时观测只在可见时用于修正夹持偏差。

### 5. 可靠性判断

“置信度”不能只是一个没有定义的标量。需要区分：

- 没检测到目标；
- 检测到多个合理目标；
- 边界被遮挡或质量不足；
- 位姿求解不稳定；
- 位姿随时间跳变；
- 图像或机器人状态过期；
- 几何上能放入，但安全余量不足；
- 已超过执行时间窗口。

这些状态会对应不同的处理方式：重新观察、调整观察角度、等待稳定、暂停接近或阻止释放。

在无法确认时拒绝释放，比输出一个错误位姿更安全。

### 6. 释放前闭环

最终流程应包含“接近、稳定、观测、调整、复测、释放”几个阶段，而不是看到一次绿色目标就立即释放。释放前的复测应重点检查：

- 中心与角度结果是否稳定；
- 用品是否保持水平；
- 图像和机器人状态是否新鲜；
- 预测投影的最小边界余量是否大于系统不确定度；
- 机器人当前位置是否会碰到已经建好的塔。

## 六、验证与决策节点

### 1. 先验证什么

应优先解决不确定性最大的部分：

1. 相机在最终安装姿态下能否稳定看见建塔处和释放点；
2. 实际绿色涂装在场地光照下的可分性；
3. 斜视和遮挡时边界角点是否稳定；
4. 相机安装外参和机器人运动学能否准确组合；
5. 夹持重复性和释放漂移是否足以支持一次放准。

如果前两项不成立，继续优化 PnP 公式没有意义；如果后两项误差过大，视觉再精确也无法转化为可靠放置。

### 2. 分层验证

| 阶段     | 验证重点                             | 通过后再做什么             |
| -------- | ------------------------------------ | -------------------------- |
| 目标检测 | 能否唯一找到当前建塔处，边界是否稳定 | 加入空间位姿               |
| 相机位姿 | 中心、方向和深度误差是否符合预期     | 加入机器人坐标链           |
| 相对定位 | 夹持和运动学误差是否被正确反映       | 做静止整机放置             |
| 整机闭环 | 最终边界余量和释放成功率             | 决定是否需要优化机构或算法 |

### 3. 测试条件

测试应覆盖：

- 不同距离、俯仰角和横向观察角；
- 塔基/中段 0°、15°、30°、45° 偏航及轻微倾斜；
- 过曝、欠曝、阴影、反光和不同色温；
- 一条或两条边界被遮挡；
- 红、蓝、灰背景以及多个绿色候选；
- 重复夹取和不同夹持偏移；
- 静止测量、运动测量和时间错位；
- 已建塔附近的接近和释放。

### 4. 评价指标

不能只看检测率，需要分别记录：

- 目标误检、漏检和目标歧义；
- 建塔处中心、偏航和倾斜误差；
- 图像到机器人状态的时间偏差；
- 夹持中心与角度偏差；
- 预测的最小边界余量；
- 实际释放后的位置偏差；
- 最终放置成功率；
- 处理时间和端到端延迟。

接近 99.9% 的目标只能通过大量整机重复试验论证，不能用单个视觉算法的平均精度代替。
如果试验样本很少，任何高成功率承诺都没有统计意义。

## 七、方案取舍与风险

### 1. 为什么不用纯二维控制

纯二维中心对齐实现简单，但在斜视、不同平面高度、箱体倾斜和释放漂移组合下容易误判安全边界。可以作为早期粗定位，但不应作为最终精确放置的唯一依据。

### 2. 为什么不先上学习模型

目标是固定颜色和几何形状，传统视觉提供的信息已经很强。没有足够真实数据时，训练模型会增加数据采集、标注、部署和故障解释成本，而且检测框仍不能直接提供精确角点和姿态。只有在实测证明传统视觉确实存在稳定不可解的漏检或分割问题时，才值得引入模型。

### 3. 为什么不把所有事情压到视觉端

夹持偏差、运动学和释放漂移属于系统问题。全部要求视觉补偿会使其承担不可观测的误差，导致算法复杂且难以调试。更合理的边界是：

- 视觉负责建塔处测量和必要的夹持校验；
- 机器人系统提供准确的末端位姿；
- 机构和标定负责降低夹持与释放误差；
- 控制层负责按最终测量完成运动和释放。

### 4. 当前最大的技术风险

按优先级排列：

1. 相机安装后实际可见范围和观察角度不足；
2. 夹持偏差和释放漂移吃掉了 45° 附近本就很小的几何余量；
3. 多个建塔处造成目标选择错误；
4. 相机与机器人状态时间不同步；
5. 绿色目标在真实光照下分割不稳定；
6. 尺寸公差使标称几何和实际边界不一致；
7. 三分钟节奏不允许为了追求单帧精度而长时间停顿。

## 八、仍需确认的问题

| 问题                                 | 为什么关键                     |
| ------------------------------------ | ------------------------------ |
| 规则附录中建塔处和用品的精确判定方式 | 决定工程安全余量是否足够保守   |
| 相机最终安装位置、视野、俯仰角和距离 | 决定检测和姿态估计可行性       |
| 相机是否随机器人臂运动而非固定在车体 | 决定外参和变换关系是否动态     |
| 夹持机构和运动学数据质量             | 决定能否通过运动学获得用品位姿 |
| 重复夹取的中心和角度偏差             | 决定能否一次放准               |
| 机构保持水平的能力和释放冲击         | 决定三维投影和倾覆风险         |
| 实际道具和场地的尺寸分布             | 决定标称模型误差               |
| 真实涂装的颜色范围及绿色干扰物       | 决定颜色分割模型               |
| 控制接口的延迟和允许的数据时效       | 决定何时必须拒绝释放           |

## 九、当前判断

当前最合理的路线是：

1. 先以建塔处视觉检测和边界稳定性作为第一验证对象；
2. 在相机标定可靠后，再建立建塔处相对相机的空间位姿；
3. 用品位姿以机器人运动学和夹持标定为主，视觉观测用于校验；
4. 最终用地面投影余量、时间时效和多帧稳定性共同决定是否释放；
5. 通过整机重复试验再决定是否需要更复杂的视觉模型、滤波或机构改进。

现阶段真正需要建设的是完整的问题模型和误差边界，而不是提前规定代码中的数据结构。只要目标选择、坐标含义、时间基准、可靠性状态和最终释放判据清晰，后续实现可以采用不同的程序结构，也可以先做独立原型再接 ROS。
