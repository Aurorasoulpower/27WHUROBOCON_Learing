## 3. 原理学习摘要

AprilTag 系统利用标签 ID、四个图像角点、相机内参和标签真实边长，通过 PnP 计算标签相对相机的三维位置和姿态。

相机标定则提供当前设备、当前分辨率下的内参和畸变参数。没有正确标定，即使标签能够被识别，估计出的距离、横向位置和朝向也可能存在系统误差。

定位链路可以概括为：

```text
相机采集
  -> 标签检测与解码
  -> 四角点和目标 ID
  -> 结合内参、畸变和标签尺寸
  -> PnP 求标签相对相机位姿
  -> 串联相机、标签和交接机构外参
  -> 得到可用于控制的相对位姿
```

本阶段完成后，前三段和 PnP 已经跑通；最后两步仍是下一阶段重点。

## 4. 去年工程精读

本阶段阅读了去年 AprilTag 相关工程，重点不是逐行记代码，而是还原完整调用链：

```text
USB/RealSense 相机
```

- 多标签筛选、有效性、时间戳、滤波、过期判断和完整外参仍然不足；
- `markerLength`、相机内参和实际分辨率是三个必须同时正确的尺度来源。

### 5.1 自己写的最小 Demo

#### 运行目的

去年工程代码较多，直接阅读不容易区分哪些环节是必要链路。因此自己实现了一个最小 Demo，
只保留 USB 相机、标定文件、标签检测、PnP、坐标换向和终端输出。

#### 运行内容

- 打开 USB 相机；
- 在启动阶段读取标定文件中的 `K`、`dist` 和 `image_size`；
- 使用 `DICT_APRILTAG_36h11` 检测标签；
- 按目标 ID 筛选标签；
- 用四角点和标签边长执行 PnP；
- 输出相机坐标、前左上坐标、yaw、重投影误差和处理耗时；
- 无目标时输出 `valid=0` 和明确原因，而不是全零位姿。

#### 结果

最小链路能够检测标签并输出有效位姿。手机显示标签时的一次有效结果为：

```text
target_id=0
x_c_mm=31.36
y_c_mm=-46.88
z_c_mm=292.27
yaw_z_deg=158.88
reproj_px=3.52
proc_ms=6.25
```

该结果显示标签在相机前方约 292 mm，并通过了默认重投影误差门槛。

手机显示标签会出现间歇性的 `no_target`。该测试只用于验证链路，不作为检测率和精度依据。

#### 新理解

- 检测标签、求位姿和得到机器人交接位置是三件不同的事；
- 相机坐标换到前左上坐标后，原点仍然是相机光心；
- 标签尺寸错误会改变距离尺度，但不影响是否能检测到标签；
- `valid=1` 只表示当前帧通过最低质量检查，不代表标定和安装外参正确；
- 明确的失败状态比输出零位姿更适合后续控制。

### 5.2 学长直连相机测试版

#### 运行目的

最小 Demo 的终端输出适合验证算法，但不便于同时观察检测框、坐标轴、时序和数值变化。
因此运行了学长编写的本地可视化测试版。

#### 运行内容

- 使用 USB 相机和已有标定文件；
- 使用 1280×720 采集目标；
- 显示相机画面、检测框、标签 ID 和标签坐标轴；
- 显示 x、y、yaw 的实时曲线；
- 显示处理耗时、图像延迟和丢帧数；
- 使用独立采集线程，只保留最新帧。

#### 调试过程

测试中曾误把 `/dev/video4` 当作目标相机。该节点实际属于笔记本红外相机，返回的是
`GREY 640×360@15`，与当前 1280×720 标定不匹配。

确认设备映射后，改为外接 `XC-CAMERA` 对应的 `/dev/video0`，检测流程恢复正常。

这次排查确认了：

- USB 设备编号会因插拔和启动顺序变化；
- 请求分辨率和实际分辨率必须分别检查；
- 实际像素格式也是判断是否选错相机的重要信息；
- 不能用另一个分辨率的内参继续计算三维位姿。

#### 达成目的

- 直观看到了从图像到检测框、坐标轴和位姿数值的完整过程；
- 确认采集与检测可以分线程处理；
- 理解了最新帧策略对降低控制延迟的意义；
- 认识到处理 FPS、图像年龄和端到端延迟是不同指标。

### 5.3 ROS 话题发布版

#### 运行目的

本地程序只能证明视觉算法能运行，还需要验证结果能否作为独立模块交给其他 ROS 程序使用。

因此运行了基于 ROS 2 的 AprilTag 发布节点，并通过 ROS CLI 和 rqt 检查话题。

#### 运行内容

- 构建 `map_matcher` 功能包；
- 启动 AprilTag 摄像头节点；
- 发布话题 `/apriltag_pose`；
- 使用 `ros2 topic list/info/echo/hz` 检查话题；
- 使用 `rqt_graph` 查看节点与话题连接；
- 使用 `rqt_plot` 查看位置字段变化。

#### 结果与认识

- 节点可以把检测结果作为 `geometry_msgs/msg/PoseStamped` 发布；
- 只有检测到标签的帧才会发布位姿；
- 没有检测结果时不会主动发布一条明确的无效消息；
- 当前消息把 `x_mm`、`y_mm` 和 `yaw_deg` 分别放进 `position.x/y/z`，不是标准三维位姿语义；
- 当前节点没有发布图像话题，因此 rqt 只能查看话题和数值，不能显示相机画面；
- 消息缺少目标 ID、有效性、重投影误差和坐标系等必要字段。

这说明“话题能发布”已经完成，但正式控制接口仍需重构。

## 6. 关键收获

1. 完整视觉模块不只是识别 ID，而是“采集、检测、位姿、质量、坐标、时序和输出”的组合。
2. 相机设备、实际分辨率、像素格式和标定文件必须作为一个整体管理。
3. 标签真实边长决定位姿尺度，不能用示例值代替实物测量。
4. 无检测时必须显式返回无效状态，控制端不能把零位姿当作正常结果。
5. 本地可视化和 ROS 检查分别解决“算法是否工作”和“结果能否交付”两个问题。
6. 视觉结果最终应以交接机构的相对位姿为目标，而不是图像中心或标签中心。

## 7. 当前问题与风险

- 目前主要使用手机显示标签，存在反光、摩尔纹和间歇漏检；
- 尚未测量实际打印标签的边长；
- 尚未完成连续 30～100 帧的检测率和位姿重复性统计；
- 当前只验证了标签相对相机位姿，没有完整的相机、标签和机构安装外参；
- ROS 消息字段和单位需要重新设计；
- 尚未接入控制端，也没有进行交接机构实际对位。

因此，本阶段可以判定为“基础链路已跑通”，但不能判定为“视觉定位精度已达到比赛使用要求”。

## 9. 阶段结论

```text
USB 相机取图

  -> PnP 位姿

  -> ROS 话题发布
```

自写 Demo 用于掌握必要链路和失败状态；学长可视化版本用于理解完整调试界面和时序；ROS 发布版用于验证模块化和后续通信接口。
