# 阶段汇报

本目录面向队长和阶段检查者，按一个完整小阶段或一段时间汇总目标、完成情况、实测证据、风险和下一步。

## 命名规范

- 跨日期阶段使用 `YYYY-MM-DD_YYYY-MM-DD_主题.md`。
- 时间边界明确且只涉及一天的阶段可以使用 `YYYY-MM-DD_主题.md`。
- 汇报文件和素材使用相同的主题名称。
- 截图、日志、图表等证据放入 `assets/主题/`。

## 记录原则

- 按阶段成果组织，不按天流水记录。
- 结论放在前面，过程只保留支撑结论所需的部分。
- 明确区分已完成、已跑通、已验证、待验证、未开始和阻塞。
- 关键结论应有命令输出、截图、数据、代码位置或提交记录作为证据。
- 未完成和失败项必须如实保留，并说明对下一阶段的影响。
- 报告应尽量独立可读，外部材料使用可访问的链接或随附证据。

## 应写内容

阶段目标与范围、完成内容、可复现的结果、关键数据和误差、技术决策、问题与风险、未验证事项、下一阶段计划和检查方式。
原理细节放入 `传感器学习/` 或 `ros2学习/`，日常素材放入 `每日记录/`，方案背景放入 `正赛思路/`。
