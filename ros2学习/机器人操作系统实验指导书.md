# 零、学生电脑安装指南

本章节仅需在第一次上实验课前完成一次。后续每次上课只需打开 Docker Desktop、启动容器即
可。

## 0.1 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10（2004版本及以上）或 Windows 11 |
| 内存 | 8GB 以上（推荐 16GB） |
| 磁盘剩余空间 | 30GB 以上（建议在非 C 盘） |
| CPU | 需支持虚拟化（大部分电脑默认已支持） |

如何查看 Windows 版本：按 Win+R ，输入 winver ，点确定。

## 0.2 步骤1：检查虚拟化是否开启

右键任务栏 → 打开"任务管理器" → 点"性能"选项卡 → 查看右下角"虚拟化"是否显示已启用。

如果显示"已禁用"，需要进入 BIOS 开启（请搜索对应品牌电脑如何在 BIOS 中开启虚拟化）。

## 0.3 步骤2：安装 WSL2

以管理员身份打开 PowerShell（右键开始菜单 → "Windows PowerShell (管理员)"），输入：

    wsl --install

⚠️ 此步骤需要从网络下载组件，可能需要 10～30 分钟，请耐心等待，不要中途关闭窗口。

安装完成后重启电脑。

重启后如果弹出 Ubuntu 窗口要求设置用户名密码，随意设置一个即可。如果没有弹出也没关系，不影响后续步骤。

验证安装成功：打开 PowerShell 输入 wsl --version ，看到 WSL 版本: 2.x.x 即为成功。

## 0.4 步骤3：安装 Docker Desktop

1. 打开浏览器，访问 https://www.docker.com/products/docker-desktop/
2. 点击 Download for Windows 下载
3. 双击安装包，安装时确保勾选 "Use WSL 2 instead of Hyper-V"
4. 安装完成后重启电脑
5. 重启后打开 Docker Desktop（开始菜单搜索"Docker Desktop"）
6. 等待左下角状态变成绿色（Engine running）

验证安装成功：打开 PowerShell 输入 docker --version ，看到版本号即为成功。

建议开机自启：Docker Desktop → 右上角齿轮 → General → 勾选 "Start Docker Desktop when
you sign in"。

## 0.5 步骤4：导入实验镜像

从老师提供的 U 盘或QQ群文件中，将 ros-lab-v4.0.tar.gz 复制到电脑桌面。

⚠️ 以下命令直接在 PowerShell 中执行，无需输入 wsl 。

    cd ~\Desktop
    docker load -i ros-lab-v4.0.tar.gz

⚠ 镜像文件较大，导入过程约需 5～10 分钟，请耐心等

待。看到 Loaded image: ros-lab:v4.0 即为成功。

确保 Docker Desktop 已启动（左下角绿色图标），然后在 PowerShell 中执行：

## 0.7 安装常见问题

Q：docker 命令提示"not recognized"或找不到命令？
A：Docker Desktop 没有启动。在开始菜单搜索 Docker Desktop 打开，等左下角绿色图标出现后再
试。

Q：docker load 提示"no such file or directory"？
A：确认当前目录是否正确。先执行 cd ~\Desktop ，再执行 docker load。也可用完整路径： docker load -i C:\Users\你的用户名\Desktop\ros-lab-v4.0.tar.gz

Q：导入镜像时提示空间不足？
A：Docker 默认把数据放在 C 盘，需要至少 30GB 剩余空间。可在 Docker Desktop → Settings →
Resources → Disk image location 改到其他盘。

Q：访问 localhost:6080 打不开页面？
A：容器可能尚未完全启动，等待约 30 秒后刷新。如仍无法打开，检查 PowerShell 窗口是否有报错信
息，并确认 docker run 命令已正确执行。

Q：仿真桌面或代码编辑器打不开？
A：容器启动需要时间，请在主页出现后再稍等 10～20 秒，再点击按钮。

Q：noVNC 画面很卡？
A：在仿真桌面页面左侧展开设置面板，把 Quality 调低。

Q：WSL 安装后没有出现 Ubuntu？
A：不影响使用。所有 docker 命令直接在 PowerShell 中执行，不需要单独使用 Ubuntu。

# 实验1：ROS2 话题通信

## 1.1 实验目的

1. 理解 ROS2 话题（Topic）的发布-订阅（Publish-Subscribe）通信模型，明确发布者与订阅者的角
色分工与协作关系
2. 能够使用 Python 独立创建 Publisher 节点和 Subscriber 节点，实现节点间的数据传递
3. 理解发布频率（Hz）的含义，掌握通过定时器精确控制消息发布速率的方法
4. 理解队列长度（Queue Size）的作用，认识消息缓存与丢失的边界条件

## 1.2 实验原理

ROS2 中最核心的通信机制之一是话题（Topic），采用发布-订阅（Pub/Sub）设计模式：

发布者（Publisher）：持续向指定话题名（如 /lab1/student_msg ）发送数据，不关心是否有
节点在监听
订阅者（Subscriber）：向 ROS2 系统声明对某话题的兴趣，每当该话题有新消息到达时，系统
自动触发回调函数处理数据

这种模式实现了节点间的松耦合：发布者和订阅者彼此不需要知道对方是否存在，也不要求同时在线，
这是分布式机器人系统设计的基础原则。

[发布者节点] ---(话题: /lab1/student_msg)---> [订阅者节点]

发布频率由定时器间隔决定：间隔 0.5 秒 → 频率 2 Hz（每秒发布2条消息）。队列长度表示当订阅者处理速度较慢时，系统缓存待处理消息的最大数量，超出后将丢弃最旧的消息。本实验使用
std_msgs/String 作为消息类型，通过 rclpy 的 create_publisher / create_subscription API
完成节点开发。

# 实验2：服务与动作通信

## 2.1 实验目的

1. 掌握 ROS2 服务（Service）的请求-响应通信模型，能够独立创建服务端（Server）与客户端
（Client）并实现完整通信流程
2. 理解同步服务调用（ call_async + spin_until_future_complete ）的使用方式，正确处理响
应数据
3. 了解动作（Action）通信机制，理解其与服务的本质区别——Action 适用于耗时操作并支持实时进
度反馈，是实验7导航的基础
4. 通过实现乘法计算服务，掌握 ROS2 接口复用的开发思路（复用现有 .srv 接口，赋予新的语义）

## 2.2 实验原理

ROS2 提供三种核心通信机制，本实验重点介绍服务与动作：

服务（Service）：同步的请求-响应通信，适合需要立即返回结果的操作。通信是一对一的：客户端
（Client）发送请求并等待服务端（Server）处理完毕后返回响应。

[客户端] ---请求(a=3, b=4)---> [服务端: 乘法服务]
[客户端] <---响应(sum=12)----- [服务端]

服务接口由 .srv 文件定义，分为请求（Request）和响应（Response）两部分，中间用 --- 分隔。本
实验复用 example_interfaces/srv/AddTwoInts 接口实现乘法运算：将 request.a × request.b
的结果存入 response.sum 字段，实现接口语义的重新解释。

动作（Action）：异步的目标-反馈-结果通信，适合耗时任务（如导航、机械臂运动）。客户端发送目
标后可以继续执行其他逻辑，服务端周期性发送进度（Feedback），任务完成后一次性返回结果
（Result）。这种非阻塞机制是实验7路径规划的通信基础。

# 实验3：机器人运动控制

## 3.1 实验目的

1. 理解 ROS2 中机器人运动控制的标准接口：通过向 /cmd_vel 话题持续发布
geometry_msgs/Twist 消息来控制机器人的线速度与角速度
2. 掌握 Twist 消息的字段含义，能够正确设置线速度（ linear.x ）和角速度（ angular.z ），理
解差速轮机器人的运动约束

4. 了解里程计（Odometry）数据的含义，学会通过订阅位置话题实现机器人状态的实时监控

## 3.2 实验原理

控制机器人移动的标准接口是 /cmd_vel 话题，消息类型为 geometry_msgs/Twist ：

Twist 消息结构：
linear.x   : 前进速度（m/s），正数=前进，负数=后退
linear.y   : 侧向速度（差速轮机器人为0，无法横向移动）
angular.z : 旋转速度（rad/s），正数=左转（逆时针），负数=右转（顺时针）
其余字段对地面机器人均为 0

本实验采用开环时间控制策略：通过控制速度指令的持续时间来估算位移和转角，而不依赖传感器反
馈。以正方形轨迹为例：

前进：linear.x = 1.0 m/s，持续 2.0 秒 → 位移约 2 米
转弯：angular.z = 1.0 rad/s，持续 π/2 秒 ≈ 1.57 秒 → 转角约 90°

这种方式简单直观，但受摩擦、传感器误差等影响会产生累积偏差。实际机器人系统通常配合里程计
（Odometry）进行闭环位置修正。本实验使用 turtlesim（二维乌龟仿真器）进行练习，其差速运动
模型与真实地面机器人保持一致，可实时在仿真桌面中观察运动效果。

# 实验4：传感器数据采集

## 4.1 实验目的

1. 掌握激光雷达（LiDAR）的工作原理及 ROS2 中 sensor_msgs/LaserScan 消息的完整字段含义，
能够正确解析距离数据与角度索引的对应关系
2. 能够从 ranges 数组中过滤无效测距值（ inf / nan 及超量程值），对有效数据进行统计计算（平
均距离、最近障碍点及其方位角）
3. 掌握通过角度范围划分方向扇区的方法，实现对前方、左方、右方三个区域的危险度独立分析
4. 将分析结果格式化为字符串并通过话题发布，完成从传感器数据订阅到分析结果输出的完整数据处
理流水线

## 4.2 实验原理

激光雷达（LiDAR）通过旋转发射激光束，测量各方向上障碍物的距离，每圈扫描产生数百至数千个距
离样本。在 ROS2 中以 sensor_msgs/LaserScan 消息表示：

LaserScan 消息结构：
angle_min       : 起始角度（弧度），通常约 -π（-180°）
angle_max       : 结束角度（弧度），通常约 π（180°）
angle_increment : 相邻测量点的角度间隔（弧度）
range_min/max   : 有效测距范围（超出此范围的测量值为 inf，需过滤）
ranges[]        : 距离值数组，ranges[i] 对应角度 angle_min + i × angle_increment

关键数据处理步骤：

1. 有效性过滤：使用 math.isfinite(r) 排除 inf / nan ，并检查 range_min < r < range_max
2. 角度-索引换算：第 i 个测距点的角度（弧度）= angle_min + i × angle_increment ，转为度数
乘以 180/π
3. 方向区域划分：前方（|angle| ≤ 30°）、左方（30° < angle ≤ 150°）、右方（-150° ≤ angle <
-30°）
4. 质心/最近点定位：遍历所有有效点，记录距离最小值及其对应角度

本实验配套的激光雷达模拟器（ lidar_simulator ）模拟真实 LiDAR 的数据格式，学生无需真实硬件
即可开发和调试算法，验证结果可在 RViz 中直观展示。

# 实验5：机器人视觉处理

## 5.1 实验目的

1. 理解数字图像的本质表示——像素三维数组及 BGR 通道顺序（ROS2 默认格式，与常见的 RGB 顺
序相反），避免处理时混淆通道
2. 掌握将 sensor_msgs/Image 消息转换为 numpy 数组的方法（ np.frombuffer + reshape ），
使用 Python 直接操作像素数据
3. 实现基于双重颜色阈值（绝对亮度 + 通道比值）的目标检测算法，能够可靠地从复杂背景中识别红
色与蓝色区域
4. 掌握目标区域质心坐标的计算方法，将检测结果格式化发布到 ROS2 话题，完成完整的视觉处理节
点开发

## 5.2 实验原理

数字图像在计算机中以三维数组存储，形状为 (高度, 宽度, 通道数) 。ROS2 的 sensor_msgs/Image
消息采用 BGR 格式（注意：与常见的 RGB 顺序相反）：

    frame[y, x, 0]   → 蓝色（Blue）通道，值范围 0~255
    frame[y, x, 1]   → 绿色（Green）通道
    frame[y, x, 2]   → 红色（Red）通道

颜色阈值检测通过比较各通道的绝对值与相对比例来区分颜色，双重条件可有效排除灰色、白色等混淆
情况：

红色条件：R > 150     且   R > G×2    且   R > B×2   （红色主导，绿蓝均弱）
蓝色条件：B > 150     且   B > R×2    且   B > G×2   （蓝色主导，红绿均弱）

质心计算（找到颜色区域的几何中心）：

满足颜色条件的像素集合 → rows, cols = np.where(mask)
质心X = int(np.mean(cols))       # 列均值 = 水平坐标
质心Y = int(np.mean(rows))       # 行均值 = 垂直坐标

本实验使用 numpy 向量化运算处理图像（比逐像素 Python 循环快数百倍），无需额外安装
OpenCV，有助于从底层理解图像处理算法的数学原理。配套的摄像头模拟器（ camera_simulator ）
生成含红球和蓝色矩形的合成图像，确保检测结果直观可验证。

# 实验6：SLAM 建图与定位

## 6.1 实验目的

1. 理解 SLAM（同时定位与建图）的基本工作原理及其在自主移动机器人中的核心作用，明确定位与
建图互相依赖的"先有鸡还是先有蛋"问题的解决思路
2. 掌握基于激光雷达数据的三方向避障控制算法，能够驱动机器人在未知房间内自主探索，尽可能扩
大地图覆盖范围
3. 学会订阅 nav_msgs/OccupancyGrid 地图消息，解析栅格数据，计算地图探索覆盖率并实时发布
4. 在 RViz 中实时观察地图从无到有的构建过程，直观理解激光雷达数据积累与地图质量的关系

## 6.2 实验原理

SLAM（Simultaneous Localization and Mapping，同时定位与建图） 是移动机器人领域的核心技
术难题：机器人在完全未知的环境中，仅靠自身传感器数据，同时解决"我在哪？"（定位）和"环境是什
么样？"（建图）两个相互耦合的问题。

激光雷达数据(/scan) → SLAM算法 → 地图(/map) + 机器人位置(/tf)

本实验采用 slam_toolbox（已配置好），学生只需负责编写驾驶控制器，让机器人移动以采集更丰富
的激光数据。控制策略：

前方安全距离（1.0 m）内：直行，速度 0.3 m/s
前方遇障：比较左右方向最小距离，选择更开阔的方向以 0.5 rad/s 转向

占用栅格地图（OccupancyGrid）将空间离散为均匀格子，每格取值：

-1 ：未知（灰色）——激光尚未扫描到此区域
0 ：空闲（白色）——确认为可通行空间
100 ：占用（黑色）——确认有障碍物

地图覆盖率 = (总格数 - 未知格数) / 总格数 × 100%，直观反映机器人对环境的探索程度。覆盖率越高，
说明机器人探索了越多区域，后续路径规划的可靠性也越高。

# 实验7：路径规划与自主导航

## 7.1 实验目的

1. 理解 ROS2 导航栈（Nav2）的整体架构，明确全局路径规划器、局部避障控制器和代价地图
（Costmap）在自主导航中各自的职责与协同关系
2. 掌握通过 Action Client 向 Nav2 发送 NavigateToPose 导航目标的完整流程，包括目标构造、异
步发送和回调绑定
3. 能够正确处理导航过程中的实时进度反馈（Feedback：剩余距离），以及最终导航结果（Result：
成功状态码 4 或失败）
4. 实现多目标点的顺序导航（链式回调），理解异步回调机制下的顺序控制逻辑

## 7.2 实验原理

Nav2（Navigation 2）是 ROS2 官方的自主导航框架，建立在实验6 SLAM 建图所得地图的基础上，包
含以下核心组件：

全局规划器（Global Planner）：基于完整地图，使用 A* 或 Dijkstra 算法计算从当前位置到目标
点的最优路径（考虑代价地图的障碍物膨胀区域）
局部控制器（DWA/MPPI）：以较高频率（约20 Hz）跟踪全局路径，并实时感知和规避动态障碍
物
代价地图（Costmap）：在地图基础上对障碍物周围进行膨胀，确保机器人轮廓不会碰到障碍物
边缘

学生通过 Action 接口与 Nav2 交互，实现非阻塞的异步导航：

[学生代码] ---Goal(目标坐标)--> [Nav2 navigate_to_pose]
[学生代码] <--Feedback(剩余距离)-- [Nav2]（导航过程中周期性发送）
[学生代码] <--Result(成功/失败)--- [Nav2]（到达或失败后发送一次）

导航结果状态码： 4 = SUCCEEDED（成功到达）； 5 = CANCELED（被取消）； 6 = ABORTED（导航
失败）。

# 实验8：机械臂抓取仿真

## 8.1 实验目的

1. 理解机器人运动学的基本概念，能够区分正向运动学（FK：关节角→末端位置）与逆向运动学
（IK：末端位置→关节角）的定义、适用场景及求解难点
2. 掌握使用余弦定理求解平面三关节机械臂逆运动学的数学推导过程，并用 Python 实现可用于实际
控制的 IK 求解函数
3. 学会通过发布 trajectory_msgs/JointTrajectory 消息控制机械臂各关节平滑运动到目标角
度，理解关节轨迹控制器的工作原理
4. 实现完整的 Pick & Place（拾取-放置）动作序列，理解多步骤机器人任务的顺序编排方式

## 8.2 实验原理

机器人运动学研究关节角度与末端执行器（手爪）位置之间的数学映射关系：

正向运动学（FK）：已知各关节角度 → 唯一确定末端位置（通过 D-H 参数矩阵推导，有解且唯
一）
逆向运动学（IK）：已知末端目标位置 → 反求关节角度（可能存在多解、无解或奇异构型）

本实验采用平面三关节机械臂（连杆长度 L1=0.4m, L2=0.3m, L3=0.2m），用几何法与余弦定理求解
IK：

IK 求解步骤：
1. 腕部坐标：wx = tx - L3,    wy = ty
2. 余弦定理求肘关节角 θ2：
cos(θ2) = (wx² + wy² - L1² - L2²) / (2×L1×L2)
若 |cos(θ2)| > 1，目标点超出工作空间，无解
3. 几何法求肩关节角 θ1：
θ1 = atan2(wy, wx) - atan2(L2·sin(θ2), L1+L2·cos(θ2))
4. θ3 = 0（末端保持水平）

关节运动指令通过 trajectory_msgs/JointTrajectory 消息发送，指定目标关节角度列表和期望运
动时间，由关节轨迹控制器（Joint Trajectory Controller）自动插值生成平滑运动轨迹。

完整抓取序列：归零（Home）→ IK 求解 → 移至目标 → 夹爪闭合 → 回归 Home → 发布完成状态。

def solve_ik_2d(self, tx, ty):
    wx, wy = tx - self.L3, ty
    dist_sq = wx**2 + wy**2

    cos_q2 = (dist_sq - self.L1**2 - self.L2**2) / (2 * self.L1 * self.L2)
    if abs(cos_q2) > 1.0:
    self.get_logger().warn(f'目标点 ({tx}, {ty}) 超出工作空间！')
    return None

    q2 = math.acos(cos_q2)
    alpha = math.atan2(wy, wx)

beta    = math.atan2(self.L2 * math.sin(q2),
    self.L1 + self.L2 * math.cos(q2))
    q1 = alpha - beta
    q3 = 0.0
    return (q1, q2, q3)
