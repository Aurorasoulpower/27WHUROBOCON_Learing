# ROS2 四大通信机制

## 一、话题（Topic）

**模型**：发布/订阅

**方向**：单向。发布者发布数据后，不知道数据是否被接收，也不知道谁在订阅。

**接口**：`.msg`

**特点**：

- 轻量，适合高频数据流
- 支持 1对1、1对n、n对1、n对n
- 同一话题所有发布者/订阅者必须使用相同接口

**典型场景**：传感器数据、状态信息、实时控制指令

## 二、服务（Service）

**模型**：客户端/服务端

**方向**：双向。客户端发请求，服务端返回响应。

**接口**：`.srv`，用 `---` 分隔请求和响应

**特点**：

- 一次请求对应一次响应
- 客户端可同步或异步等待
- 服务端默认串行，可通过回调组+多线程执行器实现并发

**典型场景**：命令调用、查询数据、短任务

**局限**：不适合长任务。执行过程中没有反馈，也不能中途取消。

## 三、参数（Parameter）

**模型**：键值对配置

**方向**：不是通信，是节点配置

**接口**：不支持自定义接口，值类型固定为 `bool`、`int64`、`float64`、`string`、`byte[]` 及数组

**特点**：

- 属于节点局部配置，不是全局
- 名字是字符串，值受类型限制
- 运行时动态生效，节点重启后丢失（除非保存/加载）
- 底层基于服务实现，但对外不暴露服务接口，用参数 CLI 或 API 操作

**典型场景**：PID 增益、速度上限、周期、阈值、设备 IP

**注意**：参数适合低频修改的配置值，不适合高频变化的控制量。

## 四、动作（Action）

**模型**：目标/反馈/结果

**方向**：双向，异步

**接口**：`.action`，用两个 `---` 分成三段：Goal、Result、Feedback

**特点**：

- 一个 Action = 三个服务 + 两个话题
- 执行过程中有实时反馈
- 支持取消
- 适合长任务

**典型场景**：导航、机械臂运动、轨迹跟踪

**注意**：ROS2 Action 标准支持取消，暂停/恢复需要自己实现，不是 Action 内置能力。

## 五、横向对比

| 维度 | 话题 | 服务 | 参数 | 动作 |
|------|------|------|------|------|
| 模型 | 发布/订阅 | 请求/响应 | 键值配置 | 目标/反馈/结果 |
| 方向 | 单向 | 双向 | 不适用 | 双向 |
| 接口 | `.msg` | `.srv` | 不支持自定义 | `.action` |
| 反馈 | 无 | 无 | 无 | 有 |
| 取消 | 不适用 | 无 | 不适用 | 有 |
| 适用时长 | 持续 | 短 | 不适用 | 长 |
| 典型场景 | 传感器数据 | 查询、命令 | 配置值 | 导航、抓取 |

## 六、一句话区分

- 持续流动的数据用**话题**
- 一次性的请求响应用**服务**
- 配置值用**参数**
- 需要过程反馈、可能中途取消的长任务用**动作**

## 七、底层关系

| 通信方式 | 底层实现 |
|----------|----------|
| 话题 | DDS 发布/订阅 |
| 服务 | DDS 请求/响应 |
| 参数 | 基于服务，ROS2 封装 |
| 动作 | 三个服务 + 两个话题，ROS2 封装 |

参数和动作都不是全新的底层机制，是 ROS2 在上层对已有机制的封装。
