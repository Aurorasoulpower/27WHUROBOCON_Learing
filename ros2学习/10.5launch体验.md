# Launch 实操记录（阶段一到六）

## 一、做了什么

在 `chapt4_ws` 下新建了 `robot_startup` 功能包，专门用来放 Launch 文件。按顺序走了六步：

1. 建包，建 `launch/` 目录
2. 写第一个 Launch 文件，启动单个参数节点
3. 修 `setup.py`，把 Launch 文件安装到 `install/`
4. 写一个 Launch 文件启动两个 Action 节点
5. 加命名空间和参数，启动两份参数节点
6. 用命令行参数控制日志级别

## 二、踩的坑

### 2.1 第一个坑：Launch 文件写完，运行报找不到

写完 `param_basic.launch.py`，直接 `colcon build` + `ros2 launch`，报错：

```
Caught exception when trying to load file of format [py]:
[Errno 2] No such file or directory:
'.../install/robot_startup/share/robot_startup/launch/param_basic.launch.py'
```

去 `install/` 下看，确实没有 `launch/` 目录。

**原因**：Python 功能包不会自动把 `launch/` 安装到 `install/`。`src/` 里写的文件，编译后不会自动过去。

**解决**：改 `setup.py`，在 `data_files` 里加一行：

```python
import os
from glob import glob

data_files=[
    ...
    (os.path.join('share', package_name, 'launch'),
        glob('launch/*.launch.py')),
],
```

`glob('launch/*.launch.py')` 收集 `launch/` 下所有 `.launch.py` 文件，安装到 `share/<包名>/launch/`。

改完重新编译，再 `ls install/robot_startup/share/robot_startup/launch/`，能看到文件了。

**这是这次实操唯一真正的坑，但很关键。** 理解了 `data_files` 和 `glob` 的作用，以后 Python 包装任何资源文件（launch、config、URDF）都要走这套。

### 2.2 一个隐性注意点：新增 launch 文件后要重新编译

`glob` 在 `setup.py` 里是在编译时扫描目录的。所以新增了 launch 文件后，必须重新 `colcon build`，否则新文件不会被安装。

### 2.3 其它没踩坑的地方

第四、五、六步都跑得比较顺，`Node`、`namespace`、`parameters`、`DeclareLaunchArgument`、`LaunchConfiguration` 这几个概念本身没出问题。

## 三、关键收获

### 3.1 Launch 文件的核心结构

```python
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    ...
    return LaunchDescription([...])
```

函数名固定，返回 `LaunchDescription`。

### 3.2 Node 的常用配置

| 参数           | 作用                              |
| -------------- | --------------------------------- |
| `package`    | 功能包名                          |
| `executable` | 可执行名                          |
| `namespace`  | 命名空间，隔离同名节点            |
| `name`       | 重命名节点                        |
| `parameters` | 传参数，`[{'key': value}]` 形式 |
| `output`     | `'screen'` 打印到终端           |
| `remappings` | 话题/节点重映射                   |

### 3.3 命令行参数的两件套

```python
DeclareLaunchArgument('arg_name', default_value='xxx', description='...')
LaunchConfiguration('arg_name')
```

前者声明，后者读取。`LaunchConfiguration` 返回的不是字符串，是延迟求值表达式，ROS2 启动时才替换。

### 3.4 安装 launch 文件的两种方式

- `ament_python` 包：`setup.py` 的 `data_files` 加 `glob`
- `ament_cmake` 包：`CMakeLists.txt` 加 `install(DIRECTORY launch DESTINATION share/${PROJECT_NAME})`

这次用的是 Python 包，练了 Python 方式。

## 四、直观感受

### 4.1 一条命令启动整个系统

之前启动参数节点、Action 服务端、Action 客户端，要开三个终端，敲三行命令，还要手动加参数。现在一条命令搞定：

```bash
ros2 launch robot_startup all.launch.py
```

这个体验的变化很直观——Launch 不是“又一个命令”，而是把散落的东西收拢起来。

### 4.2 命名空间的作用第一次感受到

第五步用 `namespace` 启动了两份参数节点，`ros2 node list` 里看到：

```
/robot1/param_basic
/robot2/param_basic
```

两个节点，同一个可执行程序，互不干扰。这是以前没用过的能力。

### 4.3 LaunchConfiguration 的延迟求值很反直觉

`LaunchConfiguration('log_level')` 返回的不是 `"20"`，是一个表达式对象。传给 `Node` 的 `parameters` 时，ROS2 会自己替换。这种“延迟求值”和普通 Python 变量完全不同，需要适应。
