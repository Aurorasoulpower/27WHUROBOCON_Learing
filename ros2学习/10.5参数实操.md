## 二、CLI 命令实操记录

### 2.1 用 turtlesim 跑通全部参数命令

```bash
# 终端一：启动模拟器
ros2 run turtlesim turtlesim_node

# 列出所有参数
ros2 param list

# 查看参数描述（类型、约束、最大最小值）
ros2 param describe /turtlesim background_b

# 获取参数值
ros2 param get /turtlesim background_b

# 设置参数值（RGB 改绿色）
ros2 param set /turtlesim background_r 44
ros2 param set /turtlesim background_g 156
ros2 param set /turtlesim background_b 10

# 导出快照（Humble 及之后默认打印到终端，需重定向保存）
ros2 param dump /turtlesim > turtlesim.yaml

# 从快照恢复
ros2 param load /turtlesim ./turtlesim.yaml

# 启动时直接加载参数文件
ros2 run turtlesim turtlesim_node --ros-args --params-file ./turtlesim.yaml
```

### 2.2 用自己写的节点跑通参数命令

```bash
# 默认运行（INFO 级别）
ros2 run example_param_rclpy param_basic

# 启动时指定 DEBUG 级别
ros2 run example_param_rclpy param_basic --ros-args -p rcl_log_level:=10

# 启动时指定 FATAL 级别
ros2 run example_param_rclpy param_basic --ros-args -p rcl_log_level:=50

# 运行中动态修改（另开终端）
ros2 param list
ros2 param set /param_basic rcl_log_level 10

# 导出快照
ros2 param dump /param_basic > param_basic.yaml

# 重启后从快照恢复
ros2 param load /param_basic ./param_basic.yaml

# 启动时加载快照
ros2 run example_param_rclpy param_basic --ros-args --params-file ./param_basic.yaml
```

## 三、踩过的坑

### 3.1 `ros2 param dump` 没生成文件

Humble 及之后版本，`dump` 默认打印到终端，不自动保存。必须用 `>` 重定向：

```bash
ros2 param dump /param_basic > param_basic.yaml
```

## 四、日志级别与数值

| 级别  | 数值                     |
| ----- | ------------------------ |
| UNSET | 0（默认，实际使用 INFO） |
| DEBUG | 10                       |
| INFO  | 20                       |
| WARN  | 30                       |
| ERROR | 40                       |
| FATAL | 50                       |

节点默认级别是 INFO（20），所以默认只打印 INFO 及以上。设成 10 则全打印，设成 50 则只有 FATAL 打印。

日志颜色是 rcutils 自带的，不同级别不同颜色。关闭颜色：

```bash
export RCUTILS_COLORIZED_OUTPUT=0
```

## 五、参数持久化链路

| 操作       | 命令                                  | 效果                 |
| ---------- | ------------------------------------- | -------------------- |
| 临时修改   | `ros2 param set`                    | 立即生效，重启丢失   |
| 保存快照   | `ros2 param dump > xxx.yaml`        | 生成文件，不生效     |
| 运行中恢复 | `ros2 param load`                   | 立即生效，重启仍丢失 |
| 启动时加载 | `--ros-args --params-file xxx.yaml` | 启动时生效，最常用   |

## 七、参数节点代码骨架

```python
import rclpy
from rclpy.node import Node
from rclpy.logging import LoggingSeverity

class ParamBasicNode(Node):
    def __init__(self, name):
        super().__init__(name)
        self.get_logger().info("节点已经启动：%s!" % name)

        # 声明参数
        self.declare_parameter('rcl_log_level', 0)

        # 启动时立即读一次，设置级别
        log_level = self.get_parameter("rcl_log_level").value
        self.get_logger().set_level(LoggingSeverity(log_level))

        # 定时器，周期性重新读参数
        self.timer = self.create_timer(0.5, self.timer_callback)

    def timer_callback(self):
        # 每次回调重新读参数，实现动态修改
        log_level = self.get_parameter("rcl_log_level").value
        self.get_logger().set_level(LoggingSeverity(log_level))

        print(f"========================{log_level}=============================")
        self.get_logger().debug("我是DEBUG级别的日志，我被打印出来了!")
        self.get_logger().info("我是INFO级别的日志，我被打印出来了!")
        self.get_logger().warn("我是WARN级别的日志，我被打印出来了!")
        self.get_logger().error("我是ERROR级别的日志，我被打印出来了!")
        self.get_logger().fatal("我是FATAL级别的日志，我被打印出来了!")

def main(args=None):
    rclpy.init(args=args)
    node = ParamBasicNode("param_basic")
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### 7.1 为什么 `__init__` 和回调里都写一遍读参数、设级别

- `__init__` 里写：启动瞬间生效，消除 0.5 秒窗口期
- 回调里写：运行中动态生效，每次重新读参数

两处不是重复，解决的是不同时间点的问题。

### 7.2 当前实现的局限

用定时器轮询实现动态修改，最长有 0.5 秒延迟，且参数变化时节点不会主动收到通知。进阶做法是用**参数回调**，参数一变立即触发，不用轮询。

## 八、参数节点 vs 服务节点横向对比

| 项目         | 服务节点              | 参数节点              |
| ------------ | --------------------- | --------------------- |
| 额外导入     | 服务接口              | 日志枚举              |
| 核心创建     | `create_service`    | `declare_parameter` |
| 是否需要接口 | 需要                  | 不需要，值类型固定    |
| 触发方式     | 客户端请求            | 定时器周期            |
| 回调参数     | `request, response` | 无                    |
| 回调返回值   | 必须有                | 无                    |
| 存属性       | `self.srv`          | `self.timer`        |
| main 结构    | 四步                  | 四步                  |

**通用规律**：所有 ROS2 Python 节点骨架相同——导入、继承 Node、构造函数、回调、main 四步、入口判断。差异只在中间创建什么对象、回调怎么触发、回调里做什么。

**通用规则**：创建的通信对象和定时器对象必须存成属性（`self.xxx = ...`），否则可能被垃圾回收。

# 参数回调改造过程总结

## 一、改造前的问题

原代码用定时器轮询实现动态修改参数：

```python
def __init__(self, name):
    ...
    self.declare_parameter('rcl_log_level', 0)
    log_level = self.get_parameter("rcl_log_level").value
    self.get_logger().set_level(log_level)
    self.timer = self.create_timer(0.5, self.timer_callback)

def timer_callback(self):
    log_level = self.get_parameter("rcl_log_level").value
    self.get_logger().set_level(log_level)
    ...
```

问题：

- 参数改了，最长等 0.5 秒才生效
- 每 0.5 秒重复打印五条日志，日志刷屏
- 读参数、设级别的逻辑在 `__init__` 和回调里各写一遍
- 参数没变时也在空转轮询

根本原因：节点不知道参数什么时候变，只能反复去问。

## 二、改造思路

从“轮询”改成“通知”：

- 参数变化时，ROS2 主动调用注册的回调
- 回调里立即处理，没有延迟
- 公共逻辑抽成一个方法，`__init__` 和回调都调用它

## 三、改造步骤

### 3.1 新增两个 import

```python
from rclpy.logging import LoggingSeverity
from rcl_interfaces.msg import SetParametersResult
```

| import                  | 作用                                     |
| ----------------------- | ---------------------------------------- |
| `LoggingSeverity`     | 日志级别枚举，把参数里的整数转成合法级别 |
| `SetParametersResult` | 参数回调的返回值类型                     |

### 3.2 删掉定时器，注册回调

```python
# 删掉
self.timer = self.create_timer(0.5, self.timer_callback)

# 换成
self.add_on_set_parameters_callback(self.param_callback)
```

注意 `self.param_callback` 没有括号，传的是方法引用，不是调用结果。

### 3.3 启动时立即应用一次

```python
self.apply_log_level(self.get_parameter("rcl_log_level").value)
```

这行是立即调用，为了让节点从第一刻起就用正确的日志级别。不是注册，不是声明，只是调用。

### 3.4 写参数回调

```python
def param_callback(self, params):
    for p in params:
        if p.name == 'rcl_log_level':
            self.apply_log_level(p.value)
            self.get_logger().info(f"日志级别已改成{p.value}")
    return SetParametersResult(successful=True)
```

关键点：

- 回调在参数被设置**之前**触发
- 回调里 `get_parameter()` 拿到的还是旧值
- 新值只能从 `p.value` 取
- 返回值必须是 `SetParametersResult`，不能是 `True`/`False`

### 3.5 抽出公共方法

```python
def apply_log_level(self, log_level):
    self.get_logger().set_level(LoggingSeverity(log_level))
    print(f"========================{log_level}=============================")
    self.get_logger().debug("我是DEBUG级别的日志")
    self.get_logger().info("我是INFO级别的日志")
    self.get_logger().warn("我是WARN级别的日志")
    self.get_logger().error("我是ERROR级别的日志")
    self.get_logger().fatal("我是FATAL级别的日志")
```

`__init__` 和 `param_callback` 都调用它，读参数、设级别的逻辑只写一遍。

## 四、验证结果

| 测试             | 命令                                             | 结果                   |
| ---------------- | ------------------------------------------------ | ---------------------- |
| 默认运行         | `ros2 run example_param_rclpy param_basic`     | 只打印一次 INFO 及以上 |
| 启动时指定 DEBUG | `... --ros-args -p rcl_log_level:=10`          | 启动即打印全部级别     |
| 运行中改参数     | `ros2 param set /param_basic rcl_log_level 10` | 立即生效，无延迟       |
| 改回 INFO        | `ros2 param set /param_basic rcl_log_level 20` | 立即只剩 INFO 及以上   |
| 改成 FATAL       | `ros2 param set /param_basic rcl_log_level 50` | 立即只剩 FATAL         |

对比轮询版：回调版不再周期打印，只在参数变化时输出，终端安静，响应即时。

## 五、轮询 vs 回调对比

| 维度           | 轮询               | 回调                       |
| -------------- | ------------------ | -------------------------- |
| 触发方式       | 节点主动查         | ROS2 主动通知              |
| 延迟           | 最大一个定时器周期 | 几乎无延迟                 |
| 定时器         | 需要               | 不需要                     |
| 参数没变时     | 仍在重复执行       | 完全静默                   |
| 能否拒绝非法值 | 不能               | 可返回`successful=False` |
| 代码重复       | 两处重复           | 抽成一个方法               |
| 适用场景       | 简单场景           | 标准做法                   |
