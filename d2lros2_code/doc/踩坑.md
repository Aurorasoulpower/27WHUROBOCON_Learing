# ROS 2 开发错误总结与避坑清单

## 一、包名 / 命名不一致（最高频）

### 错误现象

- `Package 'xxx' not found`
- `No executable found`
- `error: can't copy 'resource/xxx': doesn't exist`
- `ImportError: cannot import name ...`

### 根本原因

ROS 2 里一个包的**名字必须在 5 个地方完全一致**：

| 位置                             | 示例                     |
| -------------------------------- | ------------------------ |
| 目录名                           | `example_action_rclpy` |
| `package.xml` 的 `<name>`    | `example_action_rclpy` |
| `setup.py` 的 `package_name` | `example_action_rclpy` |
| `resource/` 下的标记文件       | `example_action_rclpy` |
| `ros2 run` 时写的包名          | `example_action_rclpy` |

### 血泪教训

- **ROS 2 包名不允许连字符 `-`**，只能用下划线 `_`。
- 一旦改了包名，上述 5 处全都要改，**还要重新 build**。

### 避坑

```bash
# 统一检查
grep -rn "旧包名" ~/ws/src/包名/
ls ~/ws/src/包名/resource/
```

## 二、接口导入路径错误

### 错误现象

- `ImportError: cannot import name 'MoveRobot'`
- `ModuleNotFoundError: No module named 'xxx.action'`

### 正确写法（背下来）

```python
# msg
from 包名.msg import 消息类型

# srv
from 包名.srv import 服务类型

# action
from 包名.action import 动作类型
```

### 错误写法

```python
from robot_control_interfaces import MoveRobot          # ❌ 顶层包没有
from rclpy.action import GoalStatus                     # ❌ Humble 里没有
```

### 版本差异要点

| 类                     | Humble 正确位置                |
| ---------------------- | ------------------------------ |
| `MoveRobot` (action) | `包名.action.MoveRobot`      |
| `GoalStatus`         | `action_msgs.msg.GoalStatus` |

## 三、拼写 / 语法错误（最容易被忽视）

### 实际踩过的坑

| 错误                                      | 正确                                        | 类型     |
| ----------------------------------------- | ------------------------------------------- | -------- |
| `MoveRobot.Feeback()`                   | `MoveRobot.Feedback()`                    | 拼写     |
| `def cancel_callback(self,goal_handle)` | `def cancel_callback(self, goal_handle):` | 缺冒号   |
| `--param-file`                          | `--params-file`                           | 参数拼写 |

### 避坑

```bash
# 编译前先查语法
python3 -m compileall ~/ws/src/包名/

# 或单个文件
python3 -m py_compile 文件.py

# 全局搜拼写
grep -rn "Feeback" ~/ws/src/
```

**Python 区分大小写**：`Feedback` ≠ `feedback` ≠ `Feeback`。

## 四、依赖 / 编译顺序问题

### 错误现象

```text
Failed to find the following files:
- .../install/robot_control_interfaces/share/.../package.sh
Check that the following packages have been built:
- robot_control_interfaces
```

### 原因

`colcon build --packages-select xxx` **不会自动编译 xxx 的依赖包**。

### 正确做法

```bash
# 方式一：整包编译（推荐）
cd ~/ws
colcon build

# 方式二：按顺序手动编译
colcon build --packages-select 接口包
source install/setup.bash
colcon build --packages-select 应用包
source install/setup.bash
```

**依赖接口包永远先编，编完必须 source。**

## 五、忘记 source 工作空间

### 错误现象

- `Package 'xxx' not found`
- 明明编译成功了还是找不到

### 原因

每开一个新终端，都需要 source：

```bash
source /opt/ros/humble/setup.bash
source ~/ws/install/setup.bash
```

### 避坑

写进 `~/.bashrc`：

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
echo "source ~/d2lros2/chapt4/chapt4_ws/install/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

⚠️ 注意：如果 `install/` 被删了，`~/.bashrc` 里的 source 会报错或产生 warning，重新 `colcon build` 即可恢复。

## 六、`ros2 param` 相关坑

### 坑 1：`dump` 不写文件

```bash
ros2 param dump /turtlesim            # 只打印到终端
ros2 param dump /turtlesim > a.yaml   # ✅ 写文件
```

### 坑 2：只读参数不能 load

```text
Set parameter qos_overrides... failed: it is read-only
```

`qos_overrides.*` 是**设计上只读**的，dump 出来能看，load 回去改不了。**这不是错误，忽略即可。**

### 坑 3：参数文件格式

```yaml
/节点名:
  ros__parameters:      # 两个下划线！
    参数名: 值
```

- 节点名前要有 `/`
- `ros__parameters` 是两个下划线
- 缩进用**空格**，不能用 Tab

## 七、终端 / 环境问题

### VSCode 集成终端 Tab 不能补全

原因：默认 shell 可能不是 bash，或没加载 `.bashrc`。

### 解决

`settings.json`：

```json
"terminal.integrated.defaultProfile.linux": "bash"
```

确保装了：

```bash
sudo apt install bash-completion
```

确保 `~/.bashrc` 里 source 了 ROS：

```bash
source /opt/ros/humble/setup.bash
```

### `WARNING: AMENT_PREFIX_PATH ... doesn't exist`

原因：`install/` 被删了，但环境变量里还留着旧路径。

解决：**新开一个终端**，或重新 build 后 source。

## 八、对工具行为的误解

### 误解 1：`ros2 pkg create --node-name xxx` 会生成完整节点

**真相**：只生成一个极简文件：

```python
def main():
    print('Hi from xxx.')

if __name__ == '__main__':
    main()
```

**不是** `rclpy` 节点模板，需要手写 `rclpy.init()`、`Node`、`spin()`。

### 误解 2：`--node-name` 可以一次生成多个

**真相**：只接收**一个**名字。多个节点需自己复制文件 + 手动加 `entry_points`。

### 误解 3：改了 `setup.py` 不重新 build 就生效

**真相**：`setup.py` 的改动**必须重新 `colcon build`** 才生效，source 是不够的。

### 误解 4：`--packages-select` 会编依赖

**真相**：只编你指定的那一个，依赖要自己先编或整包编。

## 📋 快速排查流程（贴墙版）

遇到任何 ROS 2 报错，按这个顺序查：

```bash
# 1. 当前终端 source 了吗？
echo $AMENT_PREFIX_PATH

# 2. 包在不在？
ros2 pkg list | grep 包名

# 3. 包里有可执行文件吗？
ros2 pkg executables 包名

# 4. 5 处包名一致吗？
ls src/包名/
grep '<name>' src/包名/package.xml
grep package_name src/包名/setup.py
ls src/包名/resource/

# 5. 编译成功了吗？
colcon build --packages-select 包名

# 6. import 路径写对了吗？
python3 -c "from 包名.action import 类名; print(类名)"

# 7. 语法有错吗？
python3 -m compileall src/包名/
```

## 🎯 最终建议

| 场景             | 应对                                       |
| ---------------- | ------------------------------------------ |
| 编译报错         | 看**行号 + 文件**，先查语法          |
| 运行找不到包     | 先`source`，再 `colcon build`          |
| 找不到可执行文件 | 查`setup.py` 的 `entry_points`         |
| ImportError      | 查`.msg` / `.srv` / `.action` 子模块 |
| 改了包名         | 5 处全改，删 build/install 重编            |
| 改完 setup.py    | 必须重新 build                             |
| 报错看不懂       | 复制 traceback**最下面一行**去搜     |

---

**一句话总结**：

> ROS 2 报错 90% 是这四件事——**名字不一致、import 路径错、没 source、没重新 build**。
